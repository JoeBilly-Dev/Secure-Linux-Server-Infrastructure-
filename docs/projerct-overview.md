# Project Overview

## 1. Background

This project was initiated as part of my practical learning journey in cybersecurity and Linux system administration.

The goal is to develop a secure Linux server environment while gaining hands-on experience with server configuration, network security, authentication management, database administration and security monitoring.

The project will evolve continuously as new technical skills and security concepts are learned.

## 2. Problem Statement

Servers that are not properly configured or monitored may be exposed to several security risks, including:

- Unauthorized access attempts.
- Weak authentication configurations.
- Unrestricted network access.
- Brute-force login attempts.
- Insufficient security monitoring.
- Poor security event management.

This project explores how different security technologies can work together to reduce these risks.

## 3. Project Goals

The primary objectives are:

- Establish a Linux server environment.
- Implement secure remote administration.
- Restrict unnecessary network access.
- Detect repeated authentication failures.
- Establish a database for recording security events.
- Learn to investigate system authentication logs.
- Develop automated security monitoring capabilities.

## 4. Technology Selection

| Technology | Purpose |
|---|---|
| Parrot OS | Linux server operating system |
| OpenSSH | Secure remote administration |
| UFW | Network firewall management |
| Fail2ban | Detection and temporary blocking of repeated failed login attempts |
| PostgreSQL | Security event database |
| SQL | Database management and querying |
| Python | Planned security automation |
| GitHub | Project documentation and version control |

## 5. Expected Outcome

The expected outcome is a documented and progressively hardened Linux server environment capable of supporting secure administration and basic security monitoring.

The project will also serve as practical evidence of my development in cybersecurity, Linux administration, troubleshooting and technical documentation.

## 6. Continuous Improvement

The infrastructure will be improved over time.

Each major change will be documented with:

- The reason for the change.
- The previous configuration.
- The new implementation.
- Testing and verification results.
- Lessons learned.
